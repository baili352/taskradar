## 提示词 ① 仓库初始化与首次提交

```
【角色】你是负责交付的工程师。目标是把当前项目变成一个干净、可直接提交给评审的 git 仓库，绝不把密钥、依赖、数据库、历史备份提交进去。

【当前事实】
- 项目根不是 git 仓库（git rev-parse 会失败）。
- 已存在规范 .gitignore，覆盖 .env、.env.*（!保留 .env.example）、backend/data/、*.db、.venv/、node_modules/、dist/、.screenshots/。
- 目录内有多余内容：TaskRadar_backups/（5 个备份目录，约 1.2MB）、根目录散落一张 第三阶段最终回归-前端解析结果.png、frontend/dist（构建产物）、backend/.venv（虚拟环境）。

【任务，按顺序执行】
1. 前置确认：执行 git rev-parse --is-inside-work-tree，若已是仓库则停止并报告，不要重复初始化。
2. 读取 .gitignore，逐项确认以下模式存在且生效：.env、.env.*、backend/data/、*.db、.venv/、node_modules/、dist/、.screenshots/；缺哪个就补哪个，但不得删除 !.env.example 例外规则。
3. 仓库卫生（移动，不是删除）：
   - 将 TaskRadar_backups/ 移动到项目同级目录 TaskRadar_backups_archive/，保留全部内容。
   - 将根目录 第三阶段最终回归-前端解析结果.png 移动到 .screenshots/archive/。
   - 确认 frontend/dist、backend/.venv 处于被忽略状态（用 git check-ignore -v 验证）。
4. 初始化：git init -b main；设置本仓库局部 user.name / user.email（若全局未配置，用中性值并在报告中说明）。
5. 暂存：git add -A，然后必须打印 git status --short 全量输出。
6. 敏感文件自检（硬门槛，任一命中必须处理后再提交）：
   - git ls-files | grep -E "(^|/)\.env$|\.env\.local$" → 必须为空；若命中执行 git rm --cached <文件>。
   - git ls-files | grep -E "\.db$|node_modules|\.venv/|/dist/" → 必须为空。
   - 对已暂存文件扫描密钥：git diff --cached | grep -E "sk-[A-Za-z0-9]{10,}" → 必须为空；命中则立即停止并报告，不要提交。
7. 提交：一次提交，信息为 `chore: 初始化 TaskRadar 仓库（AI + 本地 OCR 版本）`。
8. 可选：新增 MIT LICENSE，版权行写 `Copyright (c) 2026 TaskRadar`，不写个人真实姓名与邮箱。

【禁止】
- 不配置 remote、不 push、不打 tag。
- 不修改任何业务代码、配置、README 内容。
- 不使用 git add -f 强制添加被忽略文件。
- 不删除任何备份数据。

【验收输出】
1. git log --oneline 结果（应为 1 条）。
2. git ls-files | wc -l 的文件总数。
3. git count-objects -vH 的仓库体积。
4. git status 是否干净。
5. 被忽略的关键路径清单（.env / data / .venv / node_modules / dist / .screenshots 各一条 git check-ignore 验证结果）。
6. 明确回答：仓库中是否存在任何密钥、数据库文件或依赖目录。
```

## 提示词 ② 第五阶段界面截图与 README 预览

```
【角色】你是负责参赛材料的工程师。项目功能已完成，但现有 28 张截图全部属于旧的「风险提醒阶段」，大模型、本地 OCR、总览统计、演示数据这些新能力没有任何视觉证据。请补齐截图并接入 README。

【当前事实】
- 后端：backend/.venv/Scripts/python.exe 已装好依赖；启动命令 `py -3.11 -m uvicorn app.main:app --port 8000`。
- 前端：frontend 已 npm install；`npm run dev` 起在 5173，/api 走 vite 代理到 8000。
- 大模型已配置且连通（DeepSeek，实测 2050ms 成功）。
- 本地 OCR 可用（RapidOCR，实测中文 PNG 识别成功）。
- 数据库 backend/data/taskradar.db 当前有 9 事项 / 20 任务 / 16 材料 / 33 风险，演示数据 `is_demo=1` 为 0 条。
- .screenshots/ 已被 .gitignore 忽略，因此新截图要放 docs/screenshots/ 才能随仓库交付。
- README 目前没有任何截图章节。

【任务，按顺序执行】
1. 备份数据库：复制 backend/data/taskradar.db 到 TaskRadar_backups/screenshots-<时间戳>/，记录备份前后 matters/tasks/materials/risks 行数。
2. 启动后端与前端，轮询 http://127.0.0.1:8000/api/health 直到 status=ok（最多 60 秒）；确认 5173 可访问。
3. 初始化演示数据：POST http://127.0.0.1:8000/api/demo/seed，记录返回的演示事项/任务/材料/风险数量。演示数据保留不清理（现场演示要用）。
4. 用内置浏览器按 1440x900 与 390x844 两种视口截图，存到 docs/screenshots/，命名 phase5-<页面>-<宽度>.png：
   - 总览（切到「演示数据」范围，需同时出现高风险、逾期任务、材料冲突三项统计）
   - 智能分析结果（用 e2e_tests/docs/ 下一份真实 docx 上传，优先截出 analysis_mode = ai_assisted 的徽标与证据区）
   - OCR 结果（用一份清晰的中文 PNG 或扫描 PDF，必须能看到 ocr_used 标记与「第 N 页（OCR）」定位）
   - 风险详情（突出「为什么出现 / 影响什么 / 下一步做什么」三块）
   - 设置页（演示数据管理：状态、初始化、清理入口）
5. 每张截图自查：无横向溢出（document.documentElement.scrollWidth 等于视口宽度）、无控制台报错、画面中不出现 .env、API Key、base URL、本地绝对路径、浏览器书签栏。
6. 在 README 合适位置新增「界面预览」章节，用相对路径引用 docs/screenshots/ 下图片，每张配一句说明（写清这张图证明什么能力，不要只写"总览页"）。
7. 本轮只截图与改 README，不改任何业务代码。

【禁止】
- 不改业务代码、不改数据库结构、不清理演示数据。
- 不截到任何密钥、真实服务地址、个人目录路径。
- 不用设计稿、示意图、占位图冒充真实界面。

【验收输出】
1. docs/screenshots/ 文件清单与每张的像素尺寸。
2. 每张截图对应的 analysis_mode / 演示数据数量等关键佐证。
3. 备份文件路径与备份前后的数据行数对比（证明未污染正式数据）。
4. git status 中本轮新增的文件列表（应只有 docs/screenshots/ 与 README.md）。
5. 若有任何一项没截成（例如 AI 调用失败、OCR 未出结果），如实说明原因，不要用其他截图顶替。
```

## 提示词 ③ 一键启动与演示就绪

```
【角色】你是负责现场演示可靠性的工程师。现在启动要开两个终端、敲四条命令，演示时容易出错。请做成一键启动，并保证失败时有中文提示而不是黑窗口一闪而过。

【当前事实】
- Windows 环境，项目根 D:/新建文件夹/TaskRadar（脚本内用 %~dp0 相对定位，不要写死盘符）。
- 后端虚拟环境：backend/.venv/Scripts/python.exe。
- 后端启动：py -3.11 -m uvicorn app.main:app --port 8000；健康检查 http://127.0.0.1:8000/api/health。
- 前端启动：cd frontend && npm run dev，端口 5173。
- 已有 README 第四节、第五节分别讲两端的启动步骤。

【任务】
1. 新增 start.bat（放项目根）：
   - 检查 backend/.venv/Scripts/python.exe 是否存在，不存在则提示先执行安装命令并暂停退出，不要自动 pip install。
   - 检查 frontend/node_modules 是否存在，不存在同样提示。
   - 检查 8000 与 5173 是否被占用；被占用时打印中文提示（说明可能是上次未关闭）并退出，不盲目杀掉别人的进程。
   - 用 start "" 分别在新窗口启动后端与前端，后端窗口标题写「TaskRadar 后端」。
   - 循环轮询 /api/health 最多 60 秒，成功则打印「后端就绪」并用 start 打开 http://127.0.0.1:5173；超时则打印后端窗口中的错误提示建议并退出。
   - 全程不输出 .env 内容、不输出密钥。
2. 新增 stop.bat：按 8000、5173 端口查找 PID（netstat -ano），先列出将结束的进程并请求确认，再 taskkill；未占用则提示「端口已空闲」。
3. README 在第四节前新增「一键启动（推荐）」小节，说明双击 start.bat 的流程、失败时的排查顺序；保留原有的手动启动步骤作为备选。
4. 脚本只用系统自带命令，不引入第三方工具；不修改任何 Python / TypeScript 源码。

【验收输出】
1. 两个脚本的完整内容。
2. 实际执行一次 start.bat：health 返回 status=ok 的时间、前端可访问、页面能打开。
3. 实际执行一次 stop.bat：两个端口确认释放（netstat 结果）。
4. 模拟一次端口占用，说明脚本给出的中文提示是否符合预期。
5. README 改动位置与新增段落。
```
