# 公网持久部署方案（单容器同源）

> 目标：给评委一个**活到 11-29 评审结束**的固定地址，替代只能撑几小时的 Cloudflare 隧道。
> 原则：**不改任何现有业务代码**。只新增 5 个部署文件，前端构建产物与后端放在同一个容器、同一个域名下。

---

## 一、为什么是「单容器同源」而不是「前端静态托管 + 后端单独部署」

核实过代码后，方案 1（分离部署）的成本远高于表面：

| 事实 | 影响 |
| --- | --- |
| `frontend/src/api/client.ts` 所有请求都是相对路径 `/api/...`，没有任何 baseURL 拼接；全项目只有 `useSystemHealth.tsx` 读了 `VITE_API_BASE_URL`，且只用于 `/health` | 前端放到静态托管后，除健康检查外**全部接口 404**，页面能开但全坏 |
| 后端没有挂载 `StaticFiles`，`GET /` 返回 JSON | 不能靠后端直接吐前端 |
| 依赖含 `opencv-python` + `onnxruntime` | 容器缺 `libgl1` / `libglib2.0-0` / `libgomp1` 会在 import 阶段直接崩 |

更关键：平台不支持 Python，后端本来就必须另找地方跑。既然后端已经要一个能跑 Python 的容器，**把前端构建产物一起塞进同一个容器**，就得到：一个域名、同源、相对路径天然可用、CORS 不参与、零代码改动、无 159 项测试回归风险。

架构：

```
浏览器 ──► nginx :8080（唯一入口）
             ├── /              → /usr/share/nginx/html（vite build 产物）
             ├── /assets/*      → 静态资源，长缓存
             └── /api/* /docs   → 反代 http://127.0.0.1:8000（uvicorn，单 worker）
                                      └── /data/taskradar.db（持久卷，SQLite WAL）
```

## 二、需要新建的 5 个文件

### 1. `Dockerfile`（仓库根目录）

```dockerfile
# ---------- 阶段 1：构建前端 ----------
FROM node:20-alpine AS frontend
WORKDIR /build
COPY frontend/package.json frontend/package-lock.json ./
RUN npm ci
COPY frontend/ ./
# build 脚本 = tsc --noEmit && vite build，类型错误会在这里失败
RUN npm run build

# ---------- 阶段 2：运行时 ----------
FROM python:3.11-slim AS runtime
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    PIP_NO_CACHE_DIR=1

# opencv 需要 libGL/libglib，onnxruntime 需要 libgomp，缺一个启动即崩
RUN apt-get update && apt-get install -y --no-install-recommends \
        nginx curl libgl1 libglib2.0-0 libgomp1 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY backend/requirements.txt ./backend/requirements.txt
RUN pip install -r backend/requirements.txt
COPY backend/ ./backend/

COPY --from=frontend /build/dist /usr/share/nginx/html
COPY deploy/nginx.conf.template /app/deploy/nginx.conf.template
COPY deploy/entrypoint.sh /app/entrypoint.sh
RUN chmod +x /app/entrypoint.sh

ENV APP_ENV=production \
    HOST=127.0.0.1 \
    DATABASE_PATH=/data/taskradar.db \
    MATERIAL_UPLOAD_DIR=/data/uploads/materials \
    APP_TIMEZONE=Asia/Shanghai \
    MAX_UPLOAD_MB=10

VOLUME ["/data"]
EXPOSE 8080
WORKDIR /app/backend
CMD ["/app/entrypoint.sh"]
```

### 2. `deploy/nginx.conf.template`

```nginx
server {
    listen __PUBLIC_PORT__;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # 后端 MAX_UPLOAD_MB=10，nginx 默认只有 1MB，不调这里上传直接 413
    client_max_body_size 12m;

    # 后端 API：同源反代，前端相对路径 /api 直接命中
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # AI 分析单次最长 60s，含重试，默认 60s 会 502
        proxy_read_timeout 180s;
        proxy_send_timeout 180s;
        proxy_request_buffering off;
    }

    # 让评委能直接打开接口文档
    location ~ ^/(docs|redoc|openapi\.json)$ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }

    # 构建产物带 hash，可长缓存
    location /assets/ {
        expires 7d;
        add_header Cache-Control "public, max-age=604800, immutable";
        try_files $uri =404;
    }

    # index.html 不缓存，保证更新后立刻生效
    location / {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /index.html;
    }
}
```

### 3. `deploy/entrypoint.sh`

```sh
#!/bin/sh
set -eu

INTERNAL_PORT=8000
PUBLIC_PORT="${PORT:-8080}"

# 1) 持久卷挂载会盖掉镜像里的 /data，目录必须运行时创建
mkdir -p /data/uploads/materials

# 2) 生成 nginx 配置（apt 版 nginx 没有 envsubst 钩子，用 sed 最稳）
mkdir -p /etc/nginx/conf.d
rm -f /etc/nginx/sites-enabled/default
sed "s|__PUBLIC_PORT__|${PUBLIC_PORT}|g" /app/deploy/nginx.conf.template \
    > /etc/nginx/conf.d/default.conf

# 3) 后端单 worker：SQLite 写串行，多 worker 会让演示数据重复播种
cd /app/backend
uvicorn app.main:app --host 127.0.0.1 --port "${INTERNAL_PORT}" \
        --workers 1 --proxy-headers &
BACKEND_PID=$!

# 4) 等后端就绪（最多 60s）
i=0
while [ "$i" -lt 60 ]; do
    if curl -fsS "http://127.0.0.1:${INTERNAL_PORT}/api/health" >/dev/null 2>&1; then
        break
    fi
    i=$((i + 1))
    sleep 1
done

# 5) 空库自动播种演示数据：免费平台磁盘重置后仍可演示，无需人工点按钮
if curl -fsS "http://127.0.0.1:${INTERNAL_PORT}/api/demo/status" 2>/dev/null \
        | grep -q '"seeded":true'; then
    echo "[entrypoint] 演示数据已存在，跳过播种"
else
    echo "[entrypoint] 空库，执行演示数据播种"
    curl -fsS -X POST "http://127.0.0.1:${INTERNAL_PORT}/api/demo/seed?refresh=false" \
        >/dev/null || echo "[entrypoint] 播种失败，跳过（不阻塞启动）"
fi

# 6) nginx 当前台主进程；后端异常退出时随之退出，交给编排重启
( sleep 3; while kill -0 "$BACKEND_PID" 2>/dev/null; do sleep 5; done
  echo "[entrypoint] 后端已退出，关闭 nginx"; nginx -s quit ) &

exec nginx -g 'daemon off;'
```

### 4. `docker-compose.yml`（仓库根目录，VPS 用）

```yaml
services:
  taskradar:
    build: .
    image: taskradar:0.1.0
    container_name: taskradar
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      PORT: "8080"
      APP_ENV: production
      APP_TIMEZONE: Asia/Shanghai
      MAX_UPLOAD_MB: "10"
      # 大模型配置从宿主机 .env 注入，绝不写进镜像
      AI_BASE_URL: "${AI_BASE_URL:-}"
      AI_MODEL: "${AI_MODEL:-}"
      AI_API_KEY: "${AI_API_KEY:-}"
    volumes:
      - taskradar-data:/data

volumes:
  taskradar-data:
```

## 三、必须踩过的 8 个坑（漏一个就白跑）

1. **`libgl1` / `libglib2.0-0` / `libgomp1` 必装**。`opencv-python` 和 `onnxruntime` 都是二进制轮子，缺系统库不是"功能降级"，是 `import` 阶段直接崩，容器起不来。
2. **`npm ci` 依赖 `package-lock.json`**（仓库里已有，73KB），别用 `npm install`，版本漂移会让 `tsc --noEmit` 报错。
3. **`npm run build` 会先跑 `tsc --noEmit`**，任何类型错误都会让构建失败。本地 `npm run build` 能过，容器里才大概率能过。
4. **必须先 `rm -f /etc/nginx/sites-enabled/default`**。Debian 版 nginx 默认站点会抢 80 监听，导致自定义配置不生效。
5. **`client_max_body_size` 默认 1MB**。这是最容易被漏的一条，上传 2MB 的 PDF 直接 413，而本地完全正常。
6. **`proxy_read_timeout` 默认 60s**。AI 分析超时设置是 60s 且允许 1 次重试，默认值会把正常请求打成 502。
7. **SQLite 只能单 worker + 持久卷**。多 worker 会让 `POST /api/demo/seed` 并发执行，破坏"单事务原子替换"的设计；无持久卷则每次重启数据归零。
8. **持久卷会盖掉镜像里的 `/data`**。所以 `mkdir -p /data/uploads/materials` 必须放在 entrypoint 里，不能只写 Dockerfile。

## 四、三种落点

### A. 云服务器 / VPS（最稳，推荐）

```bash
# 服务器上
git clone <你的仓库> taskradar && cd taskradar
printf 'AI_BASE_URL=...\nAI_MODEL=deepseek-chat\nAI_API_KEY=...\n' > .env
docker compose up -d --build
curl -s localhost:8080/api/health
```

- 安全组放行 8080；有域名就加一层 Caddy 自动 HTTPS，省掉证书麻烦。
- 优点：常驻、秒开、无冷启动、数据持久。缺点：要钱（轻量约 ¥60–100/月）。
- **当前系统没有登录与鉴权**，公网裸奔等于任何人都能删演示数据。建议至少加一层 nginx Basic Auth：

```nginx
auth_basic "TaskRadar Demo";
auth_basic_user_file /etc/nginx/.htpasswd;
```
密码文件用 `htpasswd -c /etc/nginx/.htpasswd demo` 生成，提交帖里同时给出账号密码。

### B. Render（免费，无需信用卡）

New → Web Service → 选仓库 → Runtime: **Docker** → Instance Type: **Free** → 部署。

- 平台注入 `PORT`，entrypoint 已用 `${PORT:-8080}` 自动适配，无需改配置。
- 免费实例 **15 分钟无流量休眠**，评委首次打开要等约 50 秒冷启动。评审期建议每天手动访问一次保温。
- 免费磁盘是临时的，重新部署会重置 → 靠 entrypoint 第 5 步自动播种兜住。
- 若要求持久数据，加一个 1GB Disk 挂到 `/data`（收费项，约 $0.25/月）。

### C. Hugging Face Spaces（免费，无需信用卡）

New Space → SDK 选 **Docker** → Blank → 上传仓库 → 在 Space 的 `README.md` 里加元数据：

```yaml
---
sdk: docker
app_port: 7860
---
```

环境变量里设 `PORT=7860`（HF 要求监听 7860）。

- 免费 CPU basic，48 小时无访问休眠，唤醒约 30–60 秒。
- 磁盘同样是临时的，靠自动播种兜底。

## 五、上线验收清单（逐条实测，不要只看"部署成功"）

```bash
BASE=https://<你的域名>

curl -s -o /dev/null -w "首页 %{http_code}\n" $BASE/            # 200
curl -s $BASE/ | head -c 200                                     # 必须是 HTML，不是 JSON
curl -s $BASE/api/health                                         # database: ok
curl -s $BASE/api/demo/status                                    # seeded: true, matters > 0
curl -s $BASE/api/matters | head -c 200                          # 有数据，不是空数组
curl -s -o /dev/null -w "docs %{http_code}\n" $BASE/docs         # 200
```

浏览器侧：

- [ ] 打开首页直接看到总览有数据，不是空库引导页
- [ ] 直接访问 `$BASE/#/matters` 能进（hash 路由，不需要服务端 rewrite）
- [ ] 上传一份 **2MB 以上**的 PDF，成功且不 413
- [ ] 触发一次 AI 分析，60 秒内返回，不 502
- [ ] 窄屏 390px 下布局不塌
- [ ] `docker restart taskradar` 后数据仍在（验证持久卷）
- [ ] 关掉本机、断网，用手机 4G 打开仍然正常（验证不依赖你的电脑）

## 六、给 AI 编程工具的执行提示词

> 在 `D:/新建文件夹/TaskRadar` 下新增公网部署能力，**不要修改任何现有业务代码、路由、表结构、测试**。
>
> 新建以下文件，内容严格照抄 `.trae/documents/公网部署方案.md` 第二、三节的代码块：
> `Dockerfile`、`deploy/nginx.conf.template`、`deploy/entrypoint.sh`、`docker-compose.yml`、`.dockerignore`。
>
> 要求：
> 1. 前端在容器内用 `npm ci` + `npm run build` 构建，产物拷到 `/usr/share/nginx/html`；后端用 `uvicorn --workers 1` 监听 `127.0.0.1:8000`。
> 2. nginx 监听 `__PUBLIC_PORT__`（运行时由 entrypoint 用 `${PORT:-8080}` 替换），`/api/` 与 `/docs` 反代到后端，`client_max_body_size 12m`，`proxy_read_timeout 180s`。
> 3. 启动时若 `GET /api/demo/status` 返回 `seeded:false`，自动调 `POST /api/demo/seed?refresh=false`；失败只打日志不阻塞启动。
> 4. `.dockerignore` 必须排除 `**/.env`、`**/*.db`、`backend/data`、`node_modules`、`.git`。
> 5. 不要改动 `frontend/src/api/client.ts`，不要引入 `VITE_API_BASE_URL`——本项目同源部署，相对路径必须保持原样。
> 6. 完成后本地跑一遍 `docker compose up -d --build`，用第五节的 6 条 curl 全过一遍，把实际输出贴出来；构建失败要贴完整错误日志，不要只说"已完成"。

## 七、日常更新流程（部署之后怎么维护）

线上实例绑定的是 GitHub 仓库的 `main` 分支，**push 即部署**，没有额外的发布动作。

### 1. 改完代码，本地先验一遍

```powershell
cd D:\新建文件夹\TaskRadar\backend
.\.venv\Scripts\python.exe -m unittest discover -s tests

cd ..\frontend
npm run build      # tsc --noEmit && vite build，类型错误会在这里拦住
```

这两步和 Render 上执行的是同一套命令，本地过了线上基本不会挂。

### 2. 推送

```powershell
cd D:\新建文件夹\TaskRadar
git add -A
git commit -m "feat: 你的改动说明"
git push
```

Render 检测到 push 后自动重建，**约 2–5 分钟**（依赖层有缓存，只重建改动过的阶段；只改前端时最快）。

### 3. 盯着部署，然后验收

Render 控制台 → 你的服务 → **Events** 看构建状态。构建完成后跑：

```powershell
curl -s https://taskradar-51ll.onrender.com/api/health
curl -s https://taskradar-51ll.onrender.com/api/demo/status
```

`database: ok` + `seeded: true` 就说明新版本起来了。

### 各种改动分别会怎样

| 你改了什么 | 需要做什么 | 会不会重建 |
| --- | --- | --- |
| 前端代码、后端代码 | `git push` | 会 |
| `Dockerfile` / `nginx.conf.template` / `entrypoint.sh` | `git push` | 会，且改动风险最高，务必先本地 `docker compose up --build` |
| 大模型地址 / 模型名 / 密钥 | Render → **Environment** 改，保存 | 会（自动），不用 push |
| 只改 README 或文档 | `git push` | 会（整镜像重建，纯浪费时间，可以攒着一起推） |

### 回滚

Render 控制台 → **Events** → 找到上一个成功的 Deploy → **Rollback to this deploy**。比 `git revert` 快，而且不动仓库历史。确认是代码问题后再补一个 revert 提交，让仓库和线上保持一致。

### 三个必须知道的限制

1. **数据不持久**。免费档的磁盘是临时的，**每次重新部署 = 全新容器 = 数据库重置**，靠 entrypoint 自动重新播种演示数据兜底。所以在线上创建的真实事项、上传的材料，下次更新就没了。要保留数据，得挂一个持久磁盘到 `/data`（Render 约 $0.25/GB/月）。
2. **15 分钟无流量休眠**，唤醒 30–60 秒。评审期建议每天访问一次保温。
3. **改了环境变量也会触发重新部署**，同样会清空数据。改密钥前先想一下线上有没有要保留的东西。

### 换域名

Render 控制台 → **Settings** → **Custom Domains**，加域名后按提示在 DNS 加一条 CNAME。HTTPS 证书自动签发，不用自己配。
