> 修复状态（2026-11-14）：**F1–F4 均已修复并回归通过**。

### F1 详细说明（5 个失败检查，同一根因）

未识别的原文步骤均为“将……交至/提交至……办公室”句式：

- d02：`将纸质材料交至教务处创新创业办公室`
- d04：`将材料提交至学院科研办公室`
- d09：`将申请表和成绩单交至学院学生工作办公室`
- d10：`将申请表和成绩单交至学院办公室`
- d12：`将申请表交至行政办公室`

影响：任务少生成 1 条，用户可能漏掉“线下提交”这一关键动作。

### F2 详细说明

d09 标题为“关于提交2026年国家奖学金材料的通知”，材料提取结果包含：

```
国家奖学金申请表、成绩单、获奖证书复印件、2026年国家奖学金材料、按材料
```

后两项不是材料名称，属于标题/正文片段误匹配。

### F3 详细说明

d10 正文同时出现“2026年5月10日”和“2026年6月20日”两个截止日期，系统保存为 2026-05-10，未在备注或风险中提示存在第二个日期。该行为会使用户误以为 05-10 是唯一截止日期。

### F4 详细说明

浏览器控制台错误：

```
Warning: Each child in a list should have a unique "key" prop.
Check the render method of `RisksPage`.
at RisksPage (http://127.0.0.1:5180/src/pages/RisksPage.tsx:86:29)
```

不影响功能，但属于页面报错，演示时应修复。

### 修复状态（2026-11-14）

**F1 已修复（代码 + 回归）**

- 根因一：`sections.py` 的 `detect_metadata_line` 把“将材料交至……办公室”这类以单位名结尾的完整句子误判为落款，导致流程章节被中断。
- 根因二：`extractor.py` 的 `STEP_ACTIONS` 缺少“交至 / 送至 / 送交”动作词。
- 修复：落款识别排除含动作词的完整句子；补充上述流程动作词。
- 回归结果：d02/d04/d09/d10/d12 流程步骤数由 2/3/2/1/1 恢复为 **3/4/3/2/2**，与原文一致；隔离 API 中对应生成任务数为 3/4/3/2/2。

**F2 已修复（提取规则 + 回归）**

- 根因：材料提取会扫描标题和正文中的“按材料清单”片段，把“2026年国家奖学金材料”“按材料”当成材料名称。
- 修复：按标题特征定位标题片段并在材料提取时跳过；过滤“按 + 材料”这类介词片段。
- 回归结果：d09 材料由 5 条恢复为 **3 条**（国家奖学金申请表、成绩单、获奖证书复印件），不再包含标题片段。

**F3 已修复（提示文案 + 回归）**

- 根因：`_extract_deadline` 在存在报名区间时提前返回，未检查全文其他截止日期。
- 修复：报名区间分支同样扫描区间外的明确截止日期；若存在不同日期，写入 `deadline.note` 并补充证据。
- 回归结果：d10 截止日期仍为 2026年5月10日，备注为“原文出现多个截止日期（2026年5月10日、2026年6月20日），已取报名区间结束日 2026年5月10日，请核实。”，保存到事项后备注仍保留。

**F4 已修复（接口字段 + 回归）**

- 根因：风险详情中 `verification.checks` 未返回 `key`，前端以 `key={check.key}` 渲染时得到 `undefined`，触发 React key 警告。
- 修复：风险详情接口为每条核验项返回 `key`。
- 回归结果：隔离后端刷新风险后，`GET /api/risks/4` 的每条 `verification.checks` 均包含非空 `key`。

**回归验证**

- 新增 5 条单元测试（`backend/tests/test_p1_fixes.py::HandoverStepAndDeadlineConflictTest`），覆盖交至/提交至步骤、纯单位落款、双截止日期提示、标题材料过滤。
- 后端全量单元测试 108 项全部通过。
- 隔离后端（独立临时 DB 与 uploads）上传 5 份文档、创建事项并生成任务，全部通过；正式数据库 SHA256 仍为 `BCF4266B...AFAE18E`，未被修改。

### 非缺陷观察

- 2 次 `POST /api/risks/refresh` 显示 `signal is aborted without reason`，发生在页面切换组件卸载时，属于前端主动取消请求，随后刷新均成功，无数据影响。

- d12 非法日期 2026-02-30 未被保存层拒绝，但风险层生成 `date_unverified`，属于“允许保存 + 提示待核实”的设计选择，本次记为通过并列为观察项。
